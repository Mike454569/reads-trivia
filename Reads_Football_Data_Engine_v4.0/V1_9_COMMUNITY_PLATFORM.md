# Reads v1.9 — Community + Creator Platform

v1.9 layers community creation on top of the verified Game Factory. It does **not** replace the existing Reads UI.

## Creator workflow
1. Create a creator profile.
2. Describe a game in natural language.
3. Game Factory checks feasibility and previews source-backed puzzles.
4. Save as a community draft.
5. Submit for moderation.
6. Approve/reject/hide through moderation controls.
7. Publish a frozen puzzle pool.
8. Users play, like, save, comment, share, follow and remix.

Community creators do not provide arbitrary answer keys. Published game content is generated by the same Factory + QA pipeline as official Reads content.

## Social layer
- creator profiles and handles
- follows / following feed
- likes
- saves
- comments
- creator notifications
- share codes
- remixes with parent attribution
- creator leaderboard
- saved-game library

## Discovery
`v_community_trending` ranks approved public games using plays, completions, likes, saves, comments, quality and report penalties.

## Moderation
Public games require an approval state before publishing. Reports are recorded, and five open reports automatically return a game to `PENDING_REVIEW`.

## Community API
Run:
```bash
python community_api.py
```

Default local port: `8789`.

### Read
- `GET /v1/community/trending`
- `GET /v1/community/creators`
- `GET /v1/community/creator?user=...`
- `GET /v1/community/following?user=...`
- `GET /v1/community/saved?user=...`

### Write
- `POST /v1/community/creator`
- `POST /v1/community/create`
- `POST /v1/community/review`
- `POST /v1/community/moderate`
- `POST /v1/community/publish`
- `POST /v1/community/follow`
- `POST /v1/community/like`
- `POST /v1/community/save`
- `POST /v1/community/play/start`
- `POST /v1/community/play/complete`
- `POST /v1/community/comment`

- `POST /v1/community/share`
