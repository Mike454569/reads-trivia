## Known limitation: `source_ids` field names are Draft-shaped

The shared package builder's `source_ids` block uses field names written for the
Draft capability (`player_key`, `draft_team_code`, `draft_season`, `franchise_id`).
For Championship questions, only `franchise_id` overlaps -- the adapter's own audit
trail actually also contains `team_code`, `season`, `record`, and `playoff_result`,
which are NOT broken out into `source_ids` for this milestone. This does not affect
correctness (every fact is still fully verifiable from the question text, `notes`,
and `provenance`), and it does not affect QA (contract validation only checks the
player-facing fields, which are complete and correct). It is disclosed here rather
than silently left unexplained. Generalizing `source_ids` per-adapter was considered
during this milestone and deliberately deferred to avoid changing shared, already-
approved package-construction code beyond what was strictly required to make this
second capability executable at all (see GAME_DIRECTOR_V03_REPORT.md).
